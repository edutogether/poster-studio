# 포스터 고르기 화면(3단계) 다듬기와 포스터 디자인 7종 업그레이드

팀장 지시(Bumm님, 2026-10-14)로 시작한 작업이라 지시가 곧 승인이다(intent-workflow «팀장이 지시한 작업»).

## 문제

- «이전» 단추가 너무 작다. 글씨가 연한 회색이라 약하고, «이 포스터로 출력하기»와 높이·좌우 여백이 맞지 않는다.
- PC 화면에서 두 단추가 화면 아래에 조금 잘린다(Bumm님 캡처 `images/248.webp`).
- 포스터 8종 가운데 «시네마»만 만족스럽다. 나머지 7종(에디토리얼·컬러 블록·아치 프레임·필름스트립·폴라로이드·타이포그래피·트립틱)은
  «흔한 자동 양산형» 수준이다. 진짜 포스터 문법이 약하다: 제목 서체·크기 대비·자간, 그리드와 여백, 색 대비, 크레딧 블록.
  - 기존 진단 문서: `_docs/intents/2026-09-30-studio-design-integration/poster-quality-diagnosis-2026-10-02.md`

## 원하는 결과

1. «이전»은 진한 색(검정이나 진회색, 굵게)이고, «이 포스터로 출력하기»와 같은 높이다. 두 단추의 좌우 여백과 간격이 맞는다.
2. PC 1920×1080 · 2560×1440 · 1366×768에서 두 단추가 다 보이고, 그 아래에 여백이 남는다.
   - 제목 위치·크기, 설명 줄, 카드 간격, 단추 높이를 «알게 모르게» 조금씩 줄여서 맞춘다.
3. 7종을 세계 수준 레퍼런스를 보고 다시 설계한다. 8종이 서로 확실히 다른 성격이면서 모두 «시네마» 수준의 완성도여야 한다.
   - 레퍼런스: Criterion 커버, A24, Saul Bass·Bob Peak, 칸·베를린·선댄스·부산 영화제 공식 포스터, 한국 포스터 스튜디오(빛나는·프로파간다), Mondo 등.
   - 순서: 레퍼런스 정리 → 8개 새 시안 → 팀장 보고 → Bumm님 확인 → 코드 반영.

## 영향받는 사용자·시스템

- 행사 참가 아동·교사가 고르는 화면과 **실제로 인쇄되는 포스터**가 바뀐다(4×6 인화, 1200×1800 캔버스 = 300ppi).
- 바꾸는 곳:
  - 화면: `src/studio/StudioView.tsx`, `src/studio/*.css`
  - 포스터 조판: `src/templates.ts`(공통 도구 `src/layout.ts`)
  - 테스트: `test/poster-studio.test.tsx` 등. 포스터 화소 대조 기준선은 바뀌는 것이 정상이다.

## 제약

- 4×6 인쇄 크기(1200×1800)는 그대로 둔다.
- 로고(InKY·인천광역시교육청)와 문구(제목·주연/출연·홍보 문구·행사명·날짜·장소)는 지금 그대로 둔다. 문구를 더하지도 빼지도 않는다.
- 인쇄 해상도에서 깨지지 않아야 한다. 글자는 캔버스 글꼴로 그리고, 그림은 원화 해상도 안에서만 쓴다.
- 글꼴은 이 도메인에서 서빙되는 것만 쓴다(`font-src 'self'`). 서브셋에 없는 글자를 화면 문구에 새로 넣지 않는다(`fonts:check`).
- 실존 포스터를 베끼지 않는다. 문법(위계·그리드·빌링 블록)만 가져오고, 남의 로고·서체 파일·그림을 넣지 않는다.
- Bumm님 크롬은 쓰지 않는다. 레퍼런스는 웹 검색과 세션 브라우저로만 본다.
- push·배포는 하지 않는다(GitHub 정지). 로컬 커밋만 한다.
- 되돌릴 자리: 태그 `poster-studio-before-poster-redesign-20261014`(로컬)와 지금 화면 원본 크기 캡처.

## 미결 질문

- 7종의 새 시안을 어느 방향으로 할지는 레퍼런스 정리 뒤 Bumm님이 고른다. 시안 전에는 코드에 반영하지 않는다.
- 실제 4×6 인화 결과는 프린터 확인 전까지 «완료»로 보고하지 않는다(진단 문서 §작업 순서 4와 같음).
