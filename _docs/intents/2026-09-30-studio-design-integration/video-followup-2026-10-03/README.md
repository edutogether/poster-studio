# Poster Studio · 승인 원화 12편 영상 후속

상태: **재생 구현·제작 준비 완료, 실제 영상 0/12편. 영상 마일스톤 미완료.**

## 승인 기준과 남은 결정

- 기준은 `../loading-approved-2026-10-01/README.md`와 그 안의 `assets/sets.json`, 번호별 PNG·영상 프롬프트다. 최신 승인인 2026-10-01의 원화·문구·크기·여백을 따른다. 앞선 11번 구도 수정 지시를 되살려 재해석하지 않는다.
- 실제 앱 `src/studio/waitingSets.ts`의 원화·제목·상식을 같은 세트로 유지한다. 12개 중복 없는 순서·8초 전환·출력용 난수 분리를 보존한다.
- 3초의 실제 연속 동작, 카메라 고정·정사각형·무음. 원화의 캐릭터·포즈·소품·로고·재질을 유지한다. 역재생·왕복·정지 프레임을 늘린 파일·스프라이트 보간을 완성 영상으로 사용하지 않는다.
- `public/studio/robot-*-v2~v5.mp4`는 승인 원화보다 이전의 실험본이다. v5 제작 스크립트의 반복·역순 프레임은 이번 승인 조건에 맞지 않는다. 삭제하거나 대체하지 않고 이번 매핑에서 제외했다.
- 기존 승인 자료의 `assets/사용안내.txt`는 유료 생성 전 Bumm님 확인을 요구한다. 현재 요청은 승인되지 않은 서비스·예산을 결정하지 말고 독립 구현과 제작 자료를 먼저 완성하도록 했다. 다른 촬영 안내 영상의 Higgsfield 계획을 이 12편의 결제 승인으로 해석하지 않았다.
- **남은 결정: 사용할 이미지→영상 생성 서비스/계정, 원화 12장 전송 승인, 재생성을 포함한 총비용 상한.** 이 작업에서는 서비스 로그인·업로드·유료 생성·DB 작업을 하지 않았다. 완성 영상을 직접 제공하면 생성 비용 결정 없이 검수 단계로 진행할 수 있다.

## 재생 동작

- `src/studio/waiting-videos.json`은 현재 12항목 모두 `awaiting-generation`, `src: null`이다. 없는 MP4를 미리 요청하지 않는다.
- 검수 승인된 로컬 파일만 현재 세트에서 다운로드한다. 12편 동시 재생·선로딩은 하지 않는다. 다음 세트는 기존처럼 작은 승인 원화만 미리 읽는다.
- 원화 위에 동일한 크기·변환으로 비디오를 겹친다. 실제 `playing` 이벤트 후 180ms로 나타나며 영상 때문에 제목·상식의 위치는 달라지지 않는다.
- 3초를 정상 속도로 한 번 재생한다. 마지막 장면을 유지하고 기존 8초째에 다음 세트로 바꾼다. 이는 상식을 읽는 UI 대기 시간이며 영상 파일에 정지 프레임을 넣어 길이를 늘리는 처리가 아니다. 반복·역재생·재생속도 변경은 없다.
- 일시 정지·탭 숨김은 재생과 세트 넘김을 멈춘다. 복귀 시 재생 위치에서 이어가며 새 8초 주기를 시작한다. 움직임 줄이기는 비디오 다운로드 없이 승인 원화를 유지한다.
- 자동 재생 거부·404·디코딩 오류는 승인 원화로 복구한다. 로드/버퍼 정체가 4초 지속되면 해당 세트는 원화로 돌아간다. 무한 재시도하지 않는다. 세트 교체·생성 종료 시 비디오 소스와 재생을 정리한다.
- 생성 성공·실패·시간 제한은 기존 앱 흐름이 처리하며 이 컴포넌트가 기다리게 하지 않는다. 포스터 원화·1200×1800 출력·인쇄 코드는 변경하지 않는다.

## 반입·검수 절차

1. 원본 생성 결과는 이 후속 문서 폴더 아래 `incoming/`에 보관한다. `public/`에 검수 전 파일을 넣지 않는다. 서비스·모델·실제 비용·사용 프롬프트·원본 파일의 출처를 기록한다. 인증값은 기록하지 않는다.
2. 12편 모두 첫 장면을 지정 원화와 비교하고 전체 3초를 본다. 로고 색/모양, 손가락과 관절, 시선, 발 접지, 소품 일관성, 잘림, 흰 배경, 역재생/정지/모핑 유무를 확인한다. 자동 포맷 검사가 이 시각 검수를 대신하지 않는다.
3. 특히 07 악보 방향·오선지, 08 양손 헤드폰, 09 배낭을 잡은 오른손, 10 앞치마의 작은 공식 로고, 11 엄마/아이의 같은 진행 방향·아이 파란 짧은 목도리/신발·목 비틀림 없음, 12 마지막 조각을 붙인 뒤 그대로 남는 동작을 확인한다.
4. 납품 규격은 MP4(H.264/yuv420p), 오디오 트랙 없음, 1:1, 704~1440px, 24~30fps, 3초(인코딩 허용오차 ±0.12초), 편당 4MiB 이하, faststart다. 저사양 기기의 한 편씩 재생을 위한 기술 기준이다. 구도를 잘라 규격만 맞추거나 프레임 보간/정지 늘리기를 하지 않는다. 서비스가 3초를 지원하지 않으면 동작 전체를 보존하는 제작 방법을 먼저 재검토한다.
5. 시각 검수를 마친 파일의 SHA-256 앞 12자리를 파일명에 넣어 `public/studio/waiting-video-v1/NN-<해시12자>.mp4`로 추가한다. 같은 URL 파일을 덮어쓰지 않는다. manifest의 해당 항목에 `status: "approved"`, `src`, 전체 `sha256`, `reviewedBy`, `reviewedAt`(YYYY-MM-DD)을 기록한다. 생성했다는 이유만으로 승인 상태로 바꾸지 않는다.
6. 아래 검사와 실제 디코더/실제 로딩/뷰포트 검증을 다시 수행하고 프린트 지문 40쌍을 대조한다. 실제 12편의 원본 동일성·동작·브라우저 재생까지 확인해야 영상 마일스톤을 완료한다. 배포는 별도 승인 범위다.

```powershell
node scripts/media/check-waiting-videos.mjs
# 모든 영상이 준비된 후에만 통과해야 하는 완료 검사
node scripts/media/check-waiting-videos.mjs --require-complete
node scripts/verify/waiting-video.mjs
```

`waiting-video.mjs`의 색상 패턴은 `.cache/video-followup-checks/<실행시각>/QA-ONLY-NOT-ARTWORK.mp4`에만 만든다. 디코더·정지·오류 복구 검사에 한정하며 제작 영상으로 세지 않는다. 사용자 검토 서버는 이 파일을 제공하지 않는다.

## 검증 기록

이번 실행 결과는 `validation.md`에 기록한다. 과거 2026-10-03 배포 검증 및 프리즈 태그와 구분한다. 기존 기록을 덮어쓰지 않도록 `generation-wait.mjs`와 `release-baseline.mjs`에 선택적 `VERIFY_OUTPUT_DIR`을 추가했다. 기본 실행 동작과 비교 기준선은 그대로다.

이번 변경은 로컬 미커밋 상태로 남긴다. 커밋·푸시·병합·배포·태그 변경·승인 자산 삭제·다른 앱/공용 파일 수정은 하지 않는다.
