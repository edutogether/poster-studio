# 휴대폰 흐름 다시 짜기 — 첫 화면 한 장 · 촬영 단추 · 포스터 넘겨 보기와 저장

## 문제

월요일 공개판은 대부분 휴대폰으로 본다(Bumm님 10/17). Bumm님이 휴대폰 폭으로 직접 보고 지적했다.
- 첫 화면: 로고가 두 줄로 따로 놀고, 극장 사진이 짧아 «이번 영화의 주인공은, 나.»가 첫인상이 되지 못한다. «단독 주연 / 우리 같이» 칸이 크고 네모나다.
- 2단계: 카메라 칸이 커서 «나답게, 편하게 웃어주세요.»와 안내 1~3이 첫 화면에서 잘린다. 촬영 단추가 긴 화면 맨 아래에 있다.
- 3단계(팀장 설계 위임 «최적의 UX로»): 큰 포스터가 맨 위 · 디자인 8종이 2열 격자 · 맨 아래 «이 포스터로 출력하기» — 휴대폰에서는 인쇄가 쓸모없고, 한 화면에 안 들어온다.

## 원하는 결과

PC · 노트북 화면은 그대로 두고, 폭 760px 이하에서만:
1. 머리말: CGV × 교육청을 줄여 InKY Film Festival과 한 줄에 왼쪽 · 오른쪽으로 맞춘다(①).
2. 1단계 첫 페이지 = 머리말 + 극장 사진이 화면을 꽉 채운다. 사진 어디를 누르거나 조금만 밀면 둘째 페이지(«오늘의 주인공, 등장 !» · 영화 8개)로 세로로 착 넘어간다(②). 위로 밀면 돌아온다.
3. «단독 주연 / 우리 같이»는 낮은 가로 칸 — 아이콘 왼쪽 · 글씨 오른쪽(③).
4. 2단계: 390×844 첫 화면에 제목과 안내 1~3이 잘리지 않는다(⑤). 화면 가운데(엄지 자리)에 빨간 원형 카메라 단추 — 누르면 촬영(샘플 모드에서는 «샘플 포스터 보기»와 같은 동작)(⑥). 촬영이 끝나면 «오늘 촬영할 영화» 카드와 단추 줄까지 부드럽게 내려간다(⑦).
5. 3단계: 큰 포스터 한 장을 좌우로 밀어 넘기는 가로 스냅 넘김(이웃 포스터가 살짝 보임, 처음 한 번 살짝 움찔 — 움직임 줄이기면 생략) · 이름과 순번 · 그 아래 썸네일 한 줄(고른 것 빨간 테두리, 늘 보이게) · 포스터를 누르면 크게 보기 창(그 안에서도 좌우로) · 아래 고정 단추 줄 «← 다시 찍기» · «내 휴대폰에 저장»(파일 공유 → 안 되면 PNG 내려받기, 파일 이름 «Poster Studio_영화제목.png») · 완성 알림은 화면을 가리지 않는 짧은 알림 · 360×740 · 390×844 · 430×932 한 화면에 스크롤 없이(⑧~⑬).

## 영향받는 사용자·시스템

- 휴대폰으로 공개판(샘플 모드)을 여는 사람. 행사장 노트북(1366 이상)은 영향 없음 — PC 대조로 확인한다.
- 이 저장소 하나. 서버 · 요청 본문 · 개인정보 흐름은 바뀌지 않는다(저장은 사용자 기기 안에서만).

## 제약

- PC · 노트북 화면은 바꾸지 않는다 — 같은 흐름을 1366 · 1920 · 2560에서 찍어 출시 후보와 화소 대조한다.
- 서버로 보내는 것은 그대로 다섯 필드. 이름 · 단체명 · 출연진은 브라우저 밖으로 나가지 않는다(저장 파일 이름의 영화 제목은 사용자 기기 안에서만 쓰인다).
- 확인 · 캡처는 헤드리스로 한다(Bumm님 Chrome 금지). 라이브에서 «생성»을 누르지 않는다.
- 배포는 공개 주소와 별개인 미리보기 채널까지 — 올리기 직전 팀장에게 한 줄 보고. 라이브(master)는 건드리지 않는다.
- 움직임 줄이기 설정이면 움찔 · 부드러운 스크롤을 하지 않는다.

## 미결 질문

- 없음(팀장 설계 그대로 진행, 더 나은 방법을 쓰면 근거를 보고에 적는다).

## 만든 것과 지켜야 할 것(작업 기록)

`.claude/rules/app.md`에 옮겨 적을 내용이다 — 2026-10-17 밤 팀장 지시(«`.claude/` 파일 수정 금지», Bumm님이 창을 못 보는 동안 승인 창을 만들지 않으려고)로 여기 먼저 둔다. 일요일 확인 뒤 app.md «휴대폰 배열» 절로 옮긴다.

- 자리: `src/studio.css` 맨 끝 «휴대폰 흐름» 덩어리, `StudioView.tsx`의 `PHONE_QUERY` 갈래, `src/savePoster.ts`.
- 1단계: 첫 페이지 = 머리말 + 극장 사진. 사진을 누르거나 조금만 밀면 둘째 페이지로 세로 스냅(`html:has(body[data-step="1"])`의 `scroll-snap-type`).
  첫 페이지 높이는 `100svh - --phone-header-h` — 머리말 높이를 관찰자로 재지 않는다(위험 F 시험이 관찰자 0개를 고정). 머리말 배치를 바꾸면 이 값(123px, 370px 이하 129px)도 바꾼다.
- 2단계: 카메라 칸 `clamp(200px, 32svh, 300px)`, 엄지 자리 빨간 원형 단추 `#phoneShotBtn`(실제 모드 = 촬영, 샘플 모드 = «오늘 촬영할 영화»로 내려감), 다 찍으면 영화 카드까지 부드럽게 내려간다.
- 3단계: 큰 포스터 가로 스냅 넘김(장 크기는 남은 높이에서 — `.phone-stage`의 `container-type: size`) · 썸네일 한 줄 · «다시 찍기 / 내 휴대폰에 저장». 360×740 · 390×844 · 430×932에서 스크롤이 없다.
- PC에서는 이 요소들이 `display: none`이다. PC 화면은 같은 흐름을 `--desktop`으로 찍어 출시 후보와 화소 대조한다.
- 확인 도구 `scripts/verify/mobile-layout-probe.mjs`에 «3단계 한 화면 맞춤»·«2단계 안내 1~3 보임» 검사와 «1단계 둘째 페이지»·«원형 단추 뒤» 화면을 더했다.
- 실제 모드 확인: `mobile-layout-probe.mjs <실제 모드 빌드> <결과> --real`(가짜 카메라 · 서버 응답은 페이지 안에서 흉내). 실제 모드 2단계는 칸 안에 «카메라 켜기»가 있어
  칸 아래 글줄을 원형 단추 위로 올린다(`#cameraView .camHint.camera-example-caption`의 아래 여백 44px) — 10/17 실제 모드 검사에서 겹침을 찾았다.
