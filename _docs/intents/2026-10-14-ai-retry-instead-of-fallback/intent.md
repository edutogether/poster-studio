## 지금 동작(코드로 확인한 사실)

- **실패 화면**
  - 생성이 실패하면 오류 문구 끝에 «계속 안 되면 아래 "AI 없이 계속하기"로 진행할 수 있어요»가 붙는다.
  - 그리고 «AI 없이 기본 버전으로 계속하기» 단추가 나온다(`src/PosterStudio.tsx` `onGenerate`의 catch · `onFallback`).
  - 그 단추를 누르면 빈 그라데이션 그림(`makePlaceholderArt`)으로 8종을 만들어 인쇄까지 갈 수 있다. 인터넷이 끊겨도 이 길로 인쇄가 됐다.
- **실패해도 «사진당 2회»를 하나 쓴다.**
  - 화면은 요청 전에 횟수를 올린다(`genCountRef += 1`).
  - 서버도 요청이 들어오는 순간 사진 해시 카운터를 올리고(`checkPhotoGenerationLimit`), 실패해도 되돌리지 않는다.
  - 그래서 두 번 실패하면 그 사진으로는 더 못 만들고 다시 찍어야 한다.
  - 하루 예산 카운터(`dailyBudgetCap`)도 실패한 요청까지 센다.
- **서버는 이미 자동 재시도를 한다.**
  - OpenAI의 429·5xx면 125초 안에서 최대 4번 기다렸다 다시 부른다(`editWithRetry`).
  - 입력 조건을 거부당하면 조건을 바꿔 다시 부른다(`generateArt`).
- **실패의 종류**(`mapGenerateError` + 화면 쪽 처리)

  | 종류 | 응답 | 같은 입력으로 다시 하면 |
  |---|---|---|
  | 시간 초과 | 504 · 화면 시간 제한(150초) | 될 수 있다 |
  | 서버→OpenAI 연결 불안정 | 502 | 될 수 있다 |
  | 알 수 없는 오류 | 500 | 될 수 있다 |
  | OpenAI 혼잡 | 429 | 잠시 뒤면 될 수 있다 |
  | 우리 한도(전역 150·IP 50 / 10분) | 429 | 10분 구간이 바뀌면 된다 |
  | 사진별 한도(2회) | 429 | 안 된다 — 다시 촬영 |
  | 안전 기준(제목·문구·사진) | 400 | 안 된다 — 문구를 고치거나 다시 촬영 |
  | 하루 예산(4000건)·크레딧 부족·키 오류 | 429·500 | 안 된다 — 담당자만 고칠 수 있다 |
  | 부스 인터넷 끊김 | 화면 `TypeError` | 연결되면 된다 |

## 제안하는 흐름

1. **«AI 없이 계속하기» 단추와 빈 그라데이션 포스터를 없앤다.**
   - 실패하면 «포스터를 만들지 못했어요» 안내와 큰 «다시 만들기» 단추를 보인다(같은 사진·같은 입력).
   - 누르면 지금과 같은 로딩 화면(대기 영상)으로 다시 들어간다.
2. **실패 종류마다 다음 단추를 다르게 한다.**
   - 다시 하면 될 수 있는 것(시간 초과·연결 불안정·알 수 없음·OpenAI 혼잡): «다시 만들기».
   - 우리 한도 429: 20초를 세고 나서 «다시 만들기»가 켜진다.
   - 안전 기준: 같은 입력으로는 또 걸린다. «제목·문구 고치기»(1단계로)와 «다시 촬영»을 보인다.
   - 사진별 한도: «다시 촬영».
   - 하루 예산·크레딧·키 오류
     - 아이 화면: «잠시만 기다려 주세요 — 선생님을 불러 주세요».
     - 진행자용 원인 한 줄을 함께 보인다. 지금도 원인 문구는 있다.
3. **실패는 «사진당 2회»를 쓰지 않는다.**
   - 화면은 성공했을 때만 횟수를 올린다.
   - 서버는 생성이 실패해 오류로 답하기 직전에 그 사진의 카운터를 1 되돌린다.
   - 무한 반복은 아래 결정 3의 상한으로 막는다.
4. **인터넷이 끊겼을 때**(결정 4)
   - 사진은 노트북 메모리에 그대로 둔다(지금도 둔다).
   - «인터넷 연결이 끊겼어요»를 보이고, 5초마다 `/health`로 연결을 확인한다.
   - 연결이 돌아오면 «다시 만들기»를 켠다.
   - 진행자는 런북대로 다른 와이파이·핫스팟으로 바꾼다.
5. **바뀌지 않는 것**
   - 타임아웃 4단 체인(120 < 125 < 140 < 150초), 전역·IP 한도 값, 하루 예산 값, 서버의 자동 재시도
   - 서버로 보내는 다섯 필드(이름·단체명·출연진은 여전히 안 보냄)

## 결정 필요(Bumm님)

1. **실패한 생성이 «사진당 2회»를 쓰는가**
   - ⭐ 안 쓴다 — 성공만 센다. 서버도 실패하면 되돌린다.
   - 지금처럼 쓴다 — 두 번 실패하면 다시 촬영.
   - 근거: 아이 잘못이 아닌 실패로 재생성 기회를 잃는 것은 «다시 만들게»의 뜻과 맞지 않는다.
2. **화면이 스스로 다시 시도하는가**
   - ⭐ 안 한다. 서버가 이미 4번 재시도했으니, 실패하면 바로 «다시 만들기» 단추를 보인다.
   - 일시 오류에 한해 1번 자동으로 다시 시도한다. 아이 대기가 최대 약 4분으로 늘어난다.
3. **같은 사진으로 실패를 몇 번까지 다시 해 보는가**
   - ⭐ 실패 3번이면 «다시 촬영» 안내(진행자 확인용 원인 표시).
   - 상한 없음 — 진행자 판단에 맡긴다.
   - 근거: 원인이 고쳐지지 않은 채 줄이 계속 멈추는 것과 카운터 소모를 막는다.
4. **부스 인터넷이 끊기면**
   - ⭐ 안 A: 연결이 돌아올 때까지 기다렸다 «다시 만들기». 인쇄 우회로는 없다(지금 있던 빈 그라데이션 인쇄 길은 사라진다).
   - 안 B: 진행자만 쓰는 숨은 비상 인쇄(주소 조각 같은 스위치)를 남긴다. 그림은 아이 사진 그대로.
   - 근거
     - 대여 와이파이 2개 + 핫스팟 1개라 한쪽이 끊겨도 바꿔 탈 수 있다.
     - 빈 그라데이션 포스터는 받는 아이에게도 실망스럽다.
5. **하루 예산 카운터에서 실패를 되돌리는가**
   - ⭐ 되돌리지 않는다 — 시간 초과는 OpenAI가 그림을 다 만들어 과금했을 수도 있어, 지출 상한은 보수적으로 센다.
   - 되돌린다.
