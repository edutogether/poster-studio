# 프론트엔드를 React + TypeScript로 전환한다 (UI/UX는 체감까지 동일 유지)

> **이 문서는 늦게 쓰였다.** 규칙(`.claude/rules/intent-workflow.md` 절대 규칙 4)은
> intent를 착수 **전에** 쓰라고 한다. 실제로는 2026-09-09에 팀장 세션의 "3안 확정 — 착수"
> 지시를 받고 intent 없이 1단계(빌드 도입)까지 진행한 뒤, 같은 날 "intent를 실제로 쓰라"는
> 대표님 지시를 받아 이 문서를 쓴다. 규칙 4가 경계하는 것은 "이미 한 걸 정당화하는 글"이므로,
> 아래 **이미 확정된 것**과 **아직 앞에 있는 것**을 명시적으로 갈라 적는다. 앞의 것은 결정
> 기록이고, 뒤의 것만이 이 문서가 실제로 구속하는 범위다.

## 문제

프론트엔드가 번들러 없는 정적 ES모듈 9개(`src/*.js`, 707줄)다. 지금 이 구조 자체가
고장 난 것은 아니다 — 8차 종합감사에서 100/100을 받았다. 문제는 **앞으로 들어올 작업의
성격**이다. 대표님이 "기능 수정·추가, 프론트 디자인 수정이 엄청 들어갈 것"이라고 못박으셨고,
행사(2026-11-14)까지 두 달 남았다.

지금 구조에서 그 작업을 하면 비용이 드는 지점:

- 상태가 `state.js`의 모듈 전역과 DOM에 나뉘어 있어, 화면을 하나 고칠 때 어디를 같이
  고쳐야 하는지가 코드에 드러나지 않는다.
- 타입이 없어 `$()`가 돌려주는 것이 `null`일 수 있다는 사실이 호출부 38곳 어디에도
  적혀 있지 않다. 디자인 개편으로 DOM이 바뀌면 런타임에서야 터진다.
- 화면 조각의 경계가 함수 이름으로만 존재해서, 조각 단위로 되돌리거나 갈아끼우기 어렵다.

즉 이건 "지금이 나쁘다"가 아니라 **"앞으로 올 변경을 어느 구조가 더 잘 받아내는가"**의 문제다.
(이 판단 기준 자체가 팀장 세션의 교정을 받은 것이다 — 처음에 나는 "지금 100/100이니
건드리지 말자"를 근거로 삼았는데, 그건 앞으로 올 작업을 보지 않은 기준이었다.)

## 원하는 결과

전환이 끝났을 때:

1. `src/`가 React + TypeScript(strict)로 되어 있고, `allowJs`가 꺼져 있다.
2. **화면과 조작감이 전환 전과 구분되지 않는다.** "구분되지 않는다"는 느낌이 아니라
   아래 "증명 방법"의 3층 검증을 전부 통과했다는 뜻이다.
3. 부스 진행에 필요한 경로(카메라 열기 → 촬영 → 생성 → 인쇄/저장)가 전환 전과 같은
   횟수의 조작으로 끝난다.
4. `master` 배포가 한 번의 머지로 성립한다 — `firebase.json`·CI·`src/constants.js` 경로가
   따로 놀지 않는다.

## 영향받는 사용자·시스템

- **실사용자 있음**: 행사 당일 부스에 앉는 아동·교사. 노트북 20대(공인 IP 3개에 7/7/6).
  화면이 달라지면 부스 진행자 안내도 같이 어긋난다.
- **배포 파이프라인 전체가 바뀐다**: `firebase.json`의 hosting public이 `public` → `dist`로,
  CI가 빌드 단계를 갖게 된다. 이 셋이 한 커밋 묶음으로 가지 않으면 배포가 깨진다.
- **`functions/`는 전환 대상이 아니다** — 팀장 세션 결정. 서버 계약(엔드포인트·헤더·부스토큰)은
  그대로다. 따라서 CORS 허용 목록·레이트리밋·타임아웃 체인은 이 작업이 건드리지 않는다.
- 저장소는 이것 하나. 다만 스플래시 규격은 `_shared/standards/splash-standard.md`를 따르므로
  조직 공통 규격에 묶여 있다.

## 제약

협상 대상 아님. 지킬 수 없다는 걸 발견하면 완화하지 말고 멈추고 보고한다.

- **UI/UX가 체감까지 완전히 동일해야 한다.** 애니메이션 길이, 이징, 스크롤 감각, 전환 타이밍,
  hover/focus/tap 피드백, 반응 지연까지 포함이다.
- **다음 네 가지는 사유로 인정되지 않는다** (대표님 명시):
  "언어를 바꿨으니 이렇게밖에 안 됩니다" / "언어를 바꿨으니 깨집니다" /
  "누더기를 뜯어 고치다 보니 이렇게 됐습니다" / "일단 이렇게 하고 나중에 다듬겠습니다".
- **"깔끔하게"가 허용하는 것은 소스 구조 변경뿐이다. 결과물 변경은 허용 대상이 아니다.**
  둘이 충돌하는 것처럼 보이면 **결과가 이긴다.**
- **§15(헌법)**: "일단 동작하게", "차선책으로", "우회로", "나중에 제대로" 전부 금지.
  지금 제대로 할 수 없으면 어설픈 걸 남기지 말고 **멈추고 보고**한다.
  **범위를 줄이는 것은 대표님의 결정이지 세션의 선택이 아니다.**
- **삭제 후보는 참조 전수 조사 후 팀장 승인 전까지 삭제하지 않는다.**
- **§5.4**: 새로 만드는 테스트·게이트는 일부러 깨뜨려 실패하는 것을 확인하고 원복한다
  (변형 검증). 통과만 확인한 테스트는 이빨이 있는지 모른다.
- **§5.5**: 동일성 증명에는 눈에 보이지 않는 값이 포함돼야 한다 — `alt`, `aria-*`, `role`,
  `title`, 요소 `id` 집합, `<meta>`, 링크, `lang`, `name`/`id`/`type`/`placeholder`.
  그리고 **데이터가 채워진(`filled`) 상태**의 기준선이 필수이며 결정적으로 재현돼야 한다.
- **요소를 문서 순서로 짝지으면 안 된다** — 안정적인 키(id, 경로, 텍스트)로 짝짓는다.
- 이 앱의 기존 금지사항(`.claude/rules/app.md`)은 그대로 유효하다. 특히
  촬영 후 카메라 스트림 정지, 이름·단체명·출연진 미전송, CSP상 인라인 스크립트 금지.

순서를 이렇게 한 이유는, 전환을 시작한 뒤에 기준선을 만들면 그 기준선이 이미 오염돼

- 뷰포트 3종(1366×768 / 1024×768 / 375×812) + `filled` 1종, 총 4개 상태를 대조한다.

  스냅샷 원본은 그대로 두고 비교할 때만 정규화하며, 완화가 과한지(빈 이미지·10% 이상 변화를

## 단계 — 이미 확정된 것과 앞에 있는 것

**이미 착수·완료(브랜치 `conv/react-ts`)** — 이 문서가 뒤늦게 기록하는 부분:

- 1단계 완료: Vite + TypeScript 빌드 도입, **언어 변경 없음**(`9cb3651`).
  빌드 때문에 깨진 것과 언어를 바꿔서 깨진 것을 분리해서 보려고 일부러 쪼갰고,
  실제로 배경 이미지 404(`src/style.css`의 상대경로)가 이 단계에서 잡혀 효과가 있었다.

**아직 앞에 있는 것** — 이 문서가 구속하는 범위:

- 2단계: `src/*.js` → `.ts`(strict), 끝나면 `allowJs`를 끈다.
- 3단계: React 껍데기 전환. 아래 네 가지 위험은 **피할 이유가 아니라 구조로 없애고
  테스트로 고정할 대상**이다(이것도 팀장 세션의 교정을 받은 관점이다):
  - D 웹캠: 효과 정리에서 `getTracks().stop()` — 정지되지 않으면 실패하는 테스트를 둔다.
  - E 캔버스: StrictMode에서 정확히 한 번만 그려지는 것을 고정한다.
  - F ResizeObserver: 폭주를 실패로 재현 가능하게 만든다.
  - C 스플래시: 아래 4단계 규격대로.
- 4단계: 스플래시를 `_shared/standards/splash-standard.md`대로 교체
  (`#bootSplash` 1600ms+470ms JS 타이머 → `#splash` 1800/500/2400 CSS 애니메이션),
  **2026-09-09 개정의 로드 게이트 포함**("CSS가 시간을 재고, JS는 조건만 본다", 안전상한 약 4000ms).
  `boot-splash.js`는 번들 그래프에 들어가면 안 된다(고전 스크립트 + CSP상 인라인 불가).
  `prefers-reduced-motion` 동작을 확인해 보고한다.
- 5단계: 테스트를 React 기준으로 다시 세운다.
  **여기에 부하 테스트 확장이 붙는다**: 지금 `scripts/loadtest.mjs`는 동시성 1/2/3/5뿐이고
  지속(연속) 모드가 없어서 **"노트북 20대를 버틴다"고 주장할 수 없다.** 대표님이
  "나중에 앱 완성되면 다시 하자, 중간에 하지 말고"라고 하셨으므로 **전환 완료 후**
  동시성 20 + 지속 모드로 확장해 실행한다(20 동시 × 30분 ≈ 180건 ≈ **$7.2**,
  10분당 60건이라 전역 150 안에 들어간다). **실행 전 대표 승인 필요.**
- 6단계: CI/CSP — 빌드 산출물에 인라인 스크립트가 없음을 확인하고 라이브에서 확인한다.
  **머지·배포 직후 라이브에서 `curl`로 확인할 것**(스크린샷은 캐시에 속는다):
  `/layout-match.js`가 **404**인지 — 3단계에서 지웠고 `dist/`에 없는 것은 확인했지만,
  라이브는 아직 전환 전 파일을 서빙 중이라 배포 전에는 확인할 수 없다.
  **머지 시 문서도 같이 간다**: `CLAUDE.md`의 명령(`cd public && npm test`)과 폴더 구조,
  `.claude/rules/app.md`의 명령·배포 폴더 항목, `AGENTS.md`가 아직 `public/`이 배포
  폴더이던 시절을 가리킨다. 1단계 재구조화 이후로 브랜치에서는 이미 사실과 다르고,
  단계가 진행될수록 더 벌어진다. 코드·CI·`firebase.json`과 **같은 머지에** 넣는다 —
  이 저장소에서 "문서가 코드보다 뒤처지는 일"이 반복 발생한 항목이라 따로 적어 둔다.

### 6단계 머지 체크리스트 (2026-09-09 정리)

머지는 "브랜치를 master에 합친다"가 아니라 **배포 파이프라인의 전제를 통째로 바꾸는
일**이다. 하나라도 빠지면 머지 직후 배포가 깨지거나, 더 나쁘게는 **조용히 옛 파일이
서빙된다.** 그래서 한 줄씩 적어 둔다. 앞의 세 개는 안 하면 배포가 바로 죽는다.

| # | 무엇 | 왜 / 안 하면 |
|---|---|---|
| 1 | `firebase.json` hosting `public`: `public` → `dist` | 안 바꾸면 **빌드 결과가 아니라 정적 원본 폴더가 올라간다.** `dist/`가 없으니 배포가 실패하거나 빈 사이트가 된다 |
| 2 | CI에 `npm ci && npm run build` 단계 추가 | 지금 CI는 빌드를 모른다. `dist/`가 안 생긴다 |
| 3 | CI 스모크테스트의 부스토큰 경로 `public/constants.js` → `src/constants.ts` | 이 저장소에서 **실제로 한 번 배포를 깨뜨린 종류의 실수**다(ES모듈 전환 때) |
| 4 | `scripts/loadtest.mjs`의 상수 경로 | 위와 같은 이유. 타임아웃 4단 체인 상수가 여기 물려 있다 |
| 5 | 문서 3종: `CLAUDE.md`(명령·폴더구조), `.claude/rules/app.md`(명령·배포 폴더), `AGENTS.md` | 전부 `cd public && npm test`와 "`public/`이 배포 폴더"를 가리킨다. **코드와 같은 머지에** 넣는다 — 이 저장소는 "문서가 코드보다 뒤처지는 일"이 반복된 곳이다 |
| 6 | master의 한시적 js·css `no-cache` 규칙 제거 | 그 규칙은 "파일명에 해시가 없어서" 넣은 것이다. Vite가 해시를 붙이면 전제가 사라진다. 안 지우면 **행사장에서 매번 다시 받는다**(하루 대여 와이파이) |
| 7 | 배포 직후 `curl`로 `/layout-match.js`가 **404**인지 | 3단계에서 지웠고 `dist/`에 없는 것은 확인했지만, 배포 전에는 라이브가 아직 전환 전 파일을 서빙해서 확인할 수 없다. **스크린샷 말고 `curl`** |
| 8 | 스플래시 실시간(벽시계) 측정을 **보이는 브라우저**에서 | 브라우저 패널은 `document.hidden === true`라 **CSS 애니메이션이 아예 안 흐른다**(JS 타이머는 돈다). 패널에서 잰 값은 스플래시에 대해서는 거짓이다 |
| 9 | 폰트 검사 스크립트 위치 정리 | master는 `public/package.json`의 `fonts:charset`/`fonts:check`, 브랜치는 루트 `package.json`이다. 머지 후 `public/package.json`은 사라지므로 **루트 것만 남기고 CI에 `npm run fonts:check`를 넣는다** — 안 넣으면 문구가 바뀌어도 아무도 두부(□)를 못 잡는다 |
| 10 | `scripts/verify/poster-pixels.js`(모듈 경로판) 처리 | 머지 후에는 `/api.js`가 없어 **영영 안 돈다.** 지우거나 "master 시절 전용"이라고 못박고, 실제로 쓰는 것은 `poster-pixels-ui.js`로 한다 |
| 11 | `charset.mjs`의 경로 분기 | 브랜치판이 `src/*.ts(x)`를 훑는다. 머지 후에는 그쪽이 맞다. master판 경로(`public/*.js`)가 남아 있으면 **글자 집합이 비어 검사가 통과만 하는 빈 게이트**가 된다 |

**2단계 완료(2026-09-09, 커밋 `9b4350b`)** — `src/*.js` 10개를 `.ts`로 옮기고 `allowJs`를
