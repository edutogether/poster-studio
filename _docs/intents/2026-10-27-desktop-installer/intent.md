# Windows 설치판(`PosterStudio-Setup.exe`) · 웹 첫 화면 «↓ 다운로드» 단추 · 현장 PDF 2종

팀장 전달 Bumm님 지시(2026-10-27)라 지시 자체가 승인이다 — `accepted`를 거쳐 바로 진행한다.
기준: Hosting `836b1b9`(태그 `poster-studio-freeze-20261026-audited-100`), 함수 `81a07b4`. 작업 가지 `desktop-20261027`(836b1b9에서).

## 문제

- 행사장 인터넷이나 OpenAI가 멈추면 지금은 포스터를 하나도 못 만든다. 2026-10-16에 «AI 없이 계속하기»(빈 그라데이션 인쇄)를 없앤 뒤로는 비상 경로가 없다.
- 노트북에 설치해 둘 비상판이 필요하다. 주소만 띄우는 바로가기로는 인터넷이 끊긴 순간 같이 멈춘다.
- 그 설치 파일을 받을 자리(웹 첫 화면 단추)와, 현장 진행요원 · 교사 · 아이들이 읽을 안내물이 아직 없다.

## 원하는 결과

1. **설치판**: `PosterStudio-Setup.exe`를 더블클릭하면 Windows 10·11에 설치된다.
   - 관리자 권한 없이 사용자별로 설치된다. 설치 위치를 고를 수 있다.
   - 시작 메뉴와 바탕화면에 바로가기가 생기고, 설치가 끝나면 바로 실행된다. 일반 프로그램처럼 제거된다.
   - 인터넷이 없어도 다음 흐름이 끝까지 된다: 사진 찍기 또는 불러오기 → 포스터 8종 조판 → PC에 저장 → 인쇄 미리보기 → 인쇄.
2. **다운로드 단추**: 웹 첫 화면 «개인정보처리방침» 바로 옆에 «↓ 다운로드»가 생긴다.
   - 누르면 작은 메뉴에 «Poster Studio 설치» / «Voice Cinema 설치»가 나온다.
   - 누르기 전에는 설치 파일 요청이 0건이다. 배포하지 않는다.
3. **현장 PDF 2종**: `InKY_진행요원_교사용_매뉴얼.pdf`(A4 4쪽 이내), `InKY_아이들용_양면안내.pdf`(A4 정확히 2쪽).

## 정한 것(근거)

- **Electron을 쓴다(Tauri 아님).**
  - Electron은 웹과 같은 크로뮴을 통째로 싣고 간다. 그래서 검증을 마친 화면 · 글꼴 · 카메라 · 캔버스 조판이 그대로 돈다.
  - Tauri는 PC마다 판이 다른 WebView2 위에서 돈다. 빌드에는 Rust와 MSVC 빌드 도구(관리자 설치)가 필요한데, 이 PC에는 없다.
  - 판: electron 44.7.0(2026-10-07), electron-builder 26.17.0(2026-09-26). 둘 다 2주 넘게 지난 판이다.
- **설치판에는 AI 생성이 없다(로컬 합성만).**
  - AI를 부르려면 부스 토큰을 설치판에 넣어야 한다. 지시가 «키 · 토큰을 설치판에 넣지 않는다»다.
  - 서버의 허용 출처 목록에 설치판 출처를 더해야 하는데, 서버 함수는 바꾸지 않는다.
  - 그래서 설치판 빌드에서는 토큰 값을 비우고, 서버 확인 · 생성 요청 코드를 타지 않는다.
  - 화면 정책(CSP)도 `connect-src 'self'`로 바깥 요청을 막는다. 앱도 http · https 요청을 전부 끊는다.
- **로컬 합성**: 찍거나 불러온 사진을 그대로 8종 틀에 넣는다(`buildPosters`를 그대로 쓴다). 틀 · 글꼴 · 로고 · 인쇄 규격은 웹과 같다.
  - 설치판 화면에는 머리글에 «설치판 · AI 없이 사진 그대로»를 늘 띄운다. 웹의 AI 포스터와 헷갈리지 않게 하려는 것이다.
- **설치판에는 «샘플 포스터 보기»를 두지 않는다.**
  - 샘플 흐름은 로딩 화면에 «AI가 당신의 영화를 그리고 있어요»를 띄운다. AI가 없는 설치판에서는 거짓 표시가 된다.
  - 그래서 로딩 영상 12편도 설치판에는 싣지 않는다. 웹의 영상 · 로딩 화면은 그대로다.
- **설치판에만 있는 것**:
  - 2단계 «사진 불러오기»
  - 3단계 «PC에 저장»(저장 위치를 묻는 창이 뜬다)
  - 3단계 «인쇄 미리보기»(4×6 인화지에 놓인 모습을 보고 «인쇄하기»를 누르면 Windows 인쇄 창이 뜬다)
  - 웹 빌드에서는 이 갈래가 통째로 빠진다. 웹 번들은 다운로드 단추 말고는 바뀌지 않아야 한다(바이트 대조로 확인).
- **다운로드 단추는 웹의 1단계(첫 화면)에만 둔다.** 설치판에서는 숨긴다.
  - 단순 링크라 누르기 전에는 아무것도 받지 않는다. prefetch · preload · 서비스워커는 쓰지 않는다.
- **아이콘**: `_shared/favicons/inky-camera-512.png`(노란 InKY 로고 원본)를 그대로 쓰고 오른쪽 아래에 «PS» 배지만 얹는다.
  - 크기 · 위치 수치는 작업자료 폴더에 남겨 Voice Cinema(«VC»)와 맞춘다.

## 영향받는 사용자·시스템

- **웹**: 첫 화면에 단추 하나가 생긴다. 배포하지 않으므로 지금 라이브 사용자에게는 변화가 없다.
- **설치판 사용자**: 행사장 진행요원이 노트북에 미리 설치한다. 저장소에는 `desktop/`(Electron 껍데기)과 `src/`의 설치판 갈래가 더해진다.
- **서버 함수 · AI 지시문 · Firestore**: 바꾸지 않는다.
- **Voice Cinema**: 다운로드 메뉴 항목 주소만 가리킨다. 그 저장소는 건드리지 않는다.

## 제약

- 프로덕션 배포 · GitHub 푸시 · `gh` · master 변경은 하지 않는다. 유료 AI 생성 0건, 라이브에서 «생성»을 누르지 않는다.
- 서버 함수 · 16칸 지시문 · 승인된 UI · 8종 디자인 · 개인정보처리방침 문구를 바꾸지 않는다.
- 기존 백업 · 동결 태그 · `poster-studio-운영자-전달-20261026` PDF를 지우거나 덮어쓰지 않는다.
- 설치판에 키 · 토큰을 넣지 않는다. 코드 서명 인증서는 사지 않는다(SmartScreen 경고는 제약으로 보고).
- 설치 파일(100MB 넘음)은 저장소에 넣지 않는다. GitHub 파일 한도가 100MB다.

## 올릴 자리(제안 — 업로드 · 배포는 별도 승인)

- Hosting(`dist/`)에 넣으면 다음 CI 배포가 그 파일을 지운다. CI는 저장소에서 `dist/`를 새로 만들고, 설치 파일은 저장소에 없기 때문이다.
- 그래서 제안하는 자리:
  - 파일은 Cloud Storage(`inky-poster-studio` 프로젝트)의 공개 객체 하나에 둔다.
  - 주소는 `firebase.json` 리디렉션으로 `https://poster.edutogether.kr/download/PosterStudio-Setup.exe`에 고정한다.
- Voice Cinema 파일도 같은 방식으로 `https://voice.edutogether.kr/download/VoiceCinema-Setup.exe`에 두는 것을 제안한다(그 세션 몫).
- 단추의 두 주소는 이 제안을 따른다(`src/downloads.ts`).
