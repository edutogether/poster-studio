# 행사 당일을 실제로 재현하는 부하테스트 설계

## 문제

지금 도구로는 **"행사 당일을 버틴다"고 말할 수 없다.**

- `scripts/loadtest.mjs`는 노트북 **한 대**에서 돈다 = **공인 IP 하나**만 쓴다.
- 서버의 IP별 한도는 **50건/10분**(`IP_RATE_LIMIT_MAX`)이고, 전역은 150건/10분이다.
  **한 대에서 아무리 세게 쏴도 IP 버킷 하나만 소모**하므로, 재는 것은 "여러 대를 버티는가"가
  아니라 "IP 한도가 잘 막는가"가 된다.
- 2026-09-10에 지속(연속) 모드(`--sustain`)를 붙였지만 **이 한계는 그대로다.**

🔴 **그리고 "20대"라는 숫자가 두 가지로 쓰이고 있다.** 이것을 갈라놓지 않으면 무엇을 통과
기준으로 삼을지 정할 수 없다.

| | 실제 배치 | 스트레스 목표치 |
|---|---|---|
| 노트북 | **3대**(대표 확정 2026-09-09) | 20대 |
| 공인 IP | **3개**(대여 와이파이 2 + 핫스팟 1) | 같은 3개에 7/7/6 분산 |
| 성격 | 그날 실제로 일어나는 일 | *"압도적으로 스트레스를 줘서 문제없게"* (대표 표현) |

## 원하는 결과

**서로 다른 공인 IP 3곳에서 동시에 쏘는 테스트**를 돌려, 아래 셋을 숫자로 답할 수 있게 된다.

1. **행사 당일 부하에서 응답시간이 서버 타임아웃(120초)보다 30초 이상 여유가 있는가**
2. **한도에 걸리지 않는가** — 정상 사용 모양에서 429가 0건인가
3. **한도를 넘겼을 때 제대로 거부하고 회복하는가** — 429가 나온 뒤 다음 버킷에서 정상화되는가

### 세 갈래로 나눈다 — 같은 실행에서 볼 수 없다

| | 무엇을 재나 | 부하 모양 | 429 기대 |
|---|---|---|---|
| **A. 재현** | 그날 실제 부하 | 노트북 **3대**, 아이 한 명당 체험 1주기 | **0건이어야 정상** |
| **B. 스트레스** | 20대가 실제로 쓰는 모양 | IP 3개 × 노트북 7/7/6, 같은 주기 | **0건이어야 정상** |
| **C. 거부 동작** | 방어 장치 | 한도를 일부러 초과 | **나오는 것이 정상** |

**A·B와 C를 같은 실행에서 하면 안 된다** — C가 카운터를 태워버려 A·B의 429가 "정상 부하 때문인지
직전 C 때문인지" 구별할 수 없게 된다. 버킷이 10분이므로 **C 이후 최소 10분을 비운다.**

## 영향받는 사용자·시스템

- **실사용자 없음**(행사 전). 다만 **라이브 서버·라이브 카운터**를 쓴다 — 도는 동안 다른 부스가 429가 된다.
- **실비용이 나간다**(OpenAI 이미지 생성). 아래 비용 항목 참고.
- 건드리는 것: `scripts/loadtest.mjs`, 새 워크플로 1개, `functions/`는 **안 건드린다**(측정 대상이라 그대로 둔다).

## 어떻게 IP 3개를 만드나 — 후보와 **실측 결과**

🔴 **추측하지 않고 확인했다.** 3개인 줄 알았는데 하나면 테스트 전체가 무의미해지기 때문이다.

| 후보 | IP가 갈리는가 | 확인 |
|---|---|---|
| **GitHub Actions 병렬 잡 3개** | ✅ **갈린다** | **2026-09-11 실측** — 병렬 잡 3개가 `172.215.217.197` / `20.112.122.49` / `172.174.118.33`. 두 조회처(ipify·AWS)가 같은 값을 줬다. 워크플로: `.github/workflows/egress-ip-check.yml`(수동 실행 전용, 비용 0) |
| 클라우드 VM 3대 | 갈린다(고정 IP 지정 가능) | 미확인 — 계정·과금이 필요해 대표 처리 사항 |
| 노트북 + 모바일 테더링 2개 | 갈릴 것 | 미확인 — 행사장과 가장 비슷하지만 사람이 붙어야 한다 |
| 같은 사무실 기기 여러 대 | ❌ **안 갈린다** | 같은 NAT 뒤라 공인 IP 하나다. **"3대니까 IP 3개"라고 착각하기 쉬운 자리** |

**권고: GitHub Actions.** 무료이고, 재현 가능하고, **IP가 갈리는 것을 이미 확인**했다.

⚠ **한계를 먼저 적는다**: 러너는 데이터센터에서 돌아 **행사장 네트워크(대여 와이파이·핫스팟)보다
회선이 좋다.** 따라서 이 테스트의 응답시간은 **낙관적으로 나온다** — 서버 용량은 검증하지만
**현장 회선 품질은 검증하지 못한다.** 그쪽은 `scripts/badnet.md` 체크리스트가 담당한다.
러너 IP는 매번 달라지고 우리가 고를 수 없지만, **서로 다르다는 성질**만 필요하므로 문제되지 않는다.

## 부하 모양 — 🔴 "20 동시"와 "20대 사용"은 전혀 다르다

지금까지 `20 동시`라고 적힌 것은 **동시에 20건이 서버에서 처리 중**이라는 뜻이었다. 그런데
실제로는 아이가 촬영하고, 입력하고, 결과를 보고, 인쇄한다 — **한 대가 쉬지 않고 생성만 하지
않는다.** 두 모양의 부하량이 몇 배 차이 난다:

- **20 동시(in-flight)**: 한 건이 약 40초이므로 IP 3개 기준 **10분에 약 300건** → IP당 100건.
  **IP 한도 50을 두 배 넘는다.** 이 모양은 서버 한도가 애초에 허용하지 않으며, 그때 나오는 429는
  결함이 아니라 설계대로 동작하는 것이다. → **이건 C(거부 동작)다.**
- **20대가 실제로 쓰는 모양**: 체험 1주기를 **[확인] 분**이라 하면 10분에 `20 × (10 / 주기)`건.
  주기가 4분이면 **50건/10분**, 3분이면 67건/10분. 전역 150 안이고 IP당 17~22건이라 **429가 안 난다.**
  → **이게 B(스트레스)다.**

**주기를 모르면 B를 설계할 수 없다.** 아래 미결 질문 1번이다.

## 통과 기준 — 🔴 돌리기 전에 못박는다

결과를 보고 나서 "이 정도면 됐다"고 하지 않기 위해 미리 적는다.

| 항목 | 기준 | 근거 |
|---|---|---|
| p95 응답시간 | **90초 이하** | 서버 타임아웃 120초 − 요구 여유 30초(2026-09-06 대표 요구 기준, `loadtest.mjs`의 `REQUIRED_MARGIN_SEC`) |
| 실패율(429 제외) | **0%** | 생성 실패는 아이가 빈손으로 돌아가는 것이다 |
| 5xx | **0건** | 하나라도 나오면 원인을 밝히기 전까지 통과 아님 |
| 429 (A·B) | **0건** | 정상 사용 모양에서 한도에 걸리면 한도 산정이 틀린 것이다 |
| 429 (C) | **나와야 통과** + 다음 10분 버킷에서 **정상 복구** | 막는 것이 목적이므로 안 나오면 방어가 안 도는 것이다 |
| 임시파일 | C 실행 후 `/tmp` 누수 없음 | 429 경로의 사진 삭제는 2·7·8차 감사에서 **세 번 재발**한 자리다 |

## 비용 — 무엇 × 몇 건 × 단가

단가 **$0.04/건**(OpenAI 이미지 생성 `gpt-image-2`·medium·1024x1536·`VARIANTS=1`, 1요청=1장).
같은 단가로 `DAILY_BUDGET_MAX=4000`을 $160으로 계산해 코드에 박아 둔 값이다.

| | 건수 | 비용 |
|---|---|---|
| **A. 재현**(3대 모양, 30분) | 약 **25건** | **$1.00** |
| **B. 스트레스**(20대 모양, 30분, 주기 4분 가정) | 약 **150건** | **$6.00** |
| **C. 거부 동작**(한도 초과, 하드 상한) | 과금은 성공분만 — 최대 **450건**(150/10분 × 3버킷) | **$18.00**(상한) |
| **합계(상한)** | | **약 $25** |

429는 과금되지 않으므로 C의 실제 지출은 상한보다 낮다. **하루 예산 `DAILY_BUDGET_MAX=4000`($160)
안에 충분히 들어가며**, 세 갈래를 다 해도 그날 예산의 16%다.

## 제약

- 🔴 **실행은 대표 승인 뒤에만.** `--confirm` 없이는 도구가 거부한다(종료코드 1).
- 🔴 **행사 당일(2026-11-14)에는 절대 돌리지 않는다.**
- 🔴 **`functions/`의 한도·타임아웃 상수를 테스트를 위해 바꾸지 않는다.** 측정 대상을 고치면 측정이 아니다.
- **부스토큰을 코드·로그에 남기지 않는다** — GitHub Secrets로 넣고 마스킹을 확인한다.
- **A·B와 C 사이에 최소 10분**(버킷 롤오버)을 비운다.
- 결과에는 **"이 테스트가 검증하지 못한 것"**(현장 회선 품질, 프린터 처리량)을 반드시 함께 적는다.

## 미결 질문

1. 🔴 **아이 한 명의 체험 1주기가 몇 분인가?**(촬영 → 입력 → 생성 → 확인 → 인쇄까지) **이걸 모르면
   B의 부하 모양을 만들 수 없다.** 위 계산은 4분 가정이다.
2. **재생성 비율** — 사진 한 장당 최대 2회인데, 몇 %가 재생성을 누를 것으로 볼 것인가. 생성 건수가 그만큼 늘어난다.
3. **C(거부 동작)를 라이브에 돌릴 것인가.** 돌리는 동안 전 부스가 429가 된다. 행사 전이라 실사용자는
   없지만 결정 사항이다.
4. **A·B·C를 다 할 것인가, B만 할 것인가.** A는 부하가 작아 거의 확실히 통과하지만 **끝에서 끝까지가
   실제로 도는지**를 보는 값이 있다.
5. **GitHub Actions로 갈 것인가** — 무료·재현 가능·IP 갈림 확인 완료. 다만 회선이 좋아 응답시간이
   낙관적으로 나온다. 현장과 같은 회선으로 재려면 사람이 기기 3대를 들고 붙어야 한다.

## 하지 않기로 한 것

- **한도를 잠깐 올리고 테스트하기** — 측정 대상을 고치는 것이라 하지 않는다.
- **행사장 실제 와이파이로 사전 테스트** — 대여 회선이 행사 당일에만 있으므로 불가.
- **20 동시(in-flight)를 "정상 부하"로 재기** — 서버 한도가 허용하지 않는 모양이라 C로만 다룬다.
