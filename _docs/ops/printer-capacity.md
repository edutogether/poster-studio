# 프린터 수용량 — 대수·배터리·인화지·대기열 (2026-09-11)

행사 당일 **먼저 막히는 곳은 서버가 아니라 프린터다.** 서버는 최악에도 레이트리밋의 13~27%만
쓰는데(근거: [`_docs/intents/2026-09-11-loadtest-3ip/intent.md`](../intents/2026-09-11-loadtest-3ip/intent.md)),
**프린터가 멈추면 아이는 아무것도 받아 가지 못한다.**

## 전제

| | 값 | 출처 |
|---|---|---|
| 프린터 | 🔴 **3대** — *"구할 수 있는 게 세 대라 한 대는 알아봐야겠다. 아무래도 세 대가 최대"* | **2026-09-11 현장 확인** |
| 가동 노트북 | **4대**(+ 항시 대기 2) | 2026-09-11 대표 |
| 인쇄 1장 | **최저 1.5분 / 보통 2.0분 / 최고 3.0분** | LG 포켓포토 공식 스펙(1장 약 1분, **연속 출력 시 1~2분**) + 앞뒤 로스타임(전송·버튼·수령·용지 교체) |
| 전원 | **충전하면서 인쇄 가능. 멀티탭 준비 예정** | **2026-09-11 현장 확인** |
| 행사 | 2026-11-14, 10:30~15:00 = **270분** | |
| 부스당 예상 인원 | **약 330명**(명단 2000명 ÷ 6부스) | |

⚠ **인쇄시간은 스펙 기준이지 이 행사장 실측이 아니다.** 아래 표는 세 줄을 다 계산해 뒀으니,
**실측값이 나오면 해당 줄을 고르면 된다.**

## 1. 대수 — 3대는 **"2분 이하면 충분, 3분이면 모자람"**

**"3대로 충분하다"가 아니다.** 인쇄시간에 따라 갈린다.

| 인쇄 1장 | 시간당 | 270분 총량 | 필요 330장 대비 |
|---|---|---|---|
| 1.5분 | 120명 | **540장** | ✅ 여유 64% |
| **2.0분**(보통) | **90명** | **405장** | ✅ **여유 23%** |
| 3.0분 | 60명 | **270장** | 🔴 **60장 부족** |

🔴 **이 구성의 유일한 위험은 "인쇄가 3분까지 늘어지는 경우"다.** 그리고 그 위험은
**인쇄 한 바퀴 실측 하나가 확정하거나 없앤다**(§5, 외부 확인 대기).

**보조 시나리오 — 4대를 늦게라도 구하면**: 2.0분 540장, 3.0분에도 360장으로 **최고값에서도
모자라지 않는다.** 즉 4번째 프린터는 *"3분까지 늘어져도 괜찮게"* 만드는 보험이다.

**참고(2대였다면)**: 2.0분에 270장으로 이미 60장 부족했다 — **2대는 애초에 안 되는 구성이었다.**

### 노트북과의 균형

프린터가 노트북 4대를 따라가려면 **인쇄시간 ≤ (프린터 대수 × 노트북 한 바퀴) ÷ 4**.
**3대면 노트북 한 바퀴가 2분일 때 인쇄 1.5분까지, 3분일 때 2.25분까지** 따라간다.
그 위로는 **프린터 앞에 줄이 선다**(줄 자체의 수용 판단은 §4).

## 2. 배터리 — ✅ **확인 결과 해당 없음**(2026-09-11 현장 확인)

스펙상 **완충 시 연속 30장, 충전 90분**이라 부스당 330장이면 배터리 11개분이다.
설계 시점에는 **"충전 중에도 인쇄가 되는가"**가 갈림길이었다.

🔴 **현장 확인 결과 "충전기 꽂으면 된다. 멀티탭 준비 예정" — 갈림길이 해소됐다.**

| | 상태 |
|---|---|
| 충전하며 인쇄 **가능**(확정) | ✅ **§1의 처리량이 그대로 성립한다.** 여분 배터리·교체 시각표 **불필요** |
| ~~충전 중 정지~~ | ~~3대 기준 180장에 그쳐 150장 부족~~ → **해당 없음** |

**지우지 않고 남겨 두는 이유**: 같은 걱정이 다시 올라올 때 *"확인했고 해소됐다"*는 답이
여기 있어야 하기 때문이다.

🔴 **다만 이 해소는 전원에 걸려 있다.** **멀티탭·콘센트 확보가 운영 필수 항목**이고,
**전원이 빠지면 그 순간 배터리 제약(대당 30장)이 그대로 돌아온다.** 부스 설치 시
**프린터 3대가 동시에 꽂힐 콘센트**를 먼저 확인한다.

### 과열 — 계산에 없던 완충재 (추정)

현장 지적: **"선택하고 이름 쓰는 동안 과열된 게 식는다."** 즉 **아이가 제목을 고민하는 시간이
프린터의 냉각 시간**이 되므로, 공식 문서가 말하는 연속 출력 지연("1~2분")이 **실제로는 덜
나타날 수 있다.**

⚠ **추정이므로 위 계산에 낙관치로 반영하지 않았다.** 표는 그대로 "1.5 / 2.0 / 3.0분"으로 둔다 —
완충재가 있다는 것은 **최고값(3.0분)이 덜 나올 수 있다는 뜻**이지, 안 나온다는 보장은 아니다.

## 3. 인화지

| | 장수 |
|---|---|
| 부스당 예상 인원 | 약 330명 |
| 1인 1장 | 330장 |
| 실패·재인쇄·색 확인용 여유 **20%** | +66장 |
| **권장 준비량** | **약 400장** |
| 3대에 나눠 담으면 | **대당 약 133장** |

- **재생성(사진당 최대 2회)은 인화지를 더 쓰지 않는다** — 생성은 여러 번이어도 **인쇄는 한 번**이다.
  늘리는 요인은 재생성이 아니라 **인쇄 실패·용지 걸림·시험 출력**이다.
- ⏳ **팩 단위와 규격은 외부 확인 대기**(§5). 출력물은 **4×6** 기준이나 구매 단위(팩당 장수)는
  이 저장소에서 알 수 없다 — **400장을 채우는 팩 수**로 환산해야 한다.

## 4. 한 반이 한꺼번에 오면 — 대기열

§1은 **평균 처리량**이다. 실제로는 **한 반 30명이 동시에 온다.** 마지막 아이가 기다리는 시간:

| 인쇄 1장 | 프린터 **3대** | (참고) 4대 |
|---|---|---|
| 1.5분 | **15분** | 11분 |
| **2.0분** | **20분** | 15분 |
| 3.0분 | **30분** | 22분 |

여기에 **만드는 시간**이 겹친다(노트북 4대로 30명): 한 바퀴 2분이면 15분, 3분이면 23분,
4분이면 30분. **두 줄은 겹쳐 흐르므로 체감 대기는 둘 중 큰 쪽에 가깝다.**
보통값(인쇄 2분·한 바퀴 3분)이면 **약 23분**이다.

**현장 판단(2026-09-11)**: *"애들은 자기 것 뽑고 싶어서 기다린다. 실제로 큰 불만은 아닐 것"* —
**기다림 자체를 실패로 보지 않는다.** 다만 **숫자는 남긴다** — 그 판단의 근거이고,
인쇄가 3분으로 늘어지면 **30분**이 되어 판단의 전제가 달라지기 때문이다.

**운영 쪽 완충책**(앱이 아니라 진행 방식):
- 번호표·호출로 **줄 서서 기다리지 않게** 한다(만든 뒤 다른 부스를 돌고 오게).
- 한 반을 **두 줄로 나눠** 받으면 체감이 절반이 된다.
- **인쇄 대기 중에도 다음 아이가 촬영·생성을 시작할 수 있다** — 노트북과 프린터는 분리돼 있다.

## 5. 확인 상태

| | 상태 |
|---|---|
| 충전하면서 인쇄되는가 | ✅ **된다**(2026-09-11 현장 확인, 멀티탭 준비) |
| 프린터 대수 | ✅ **3대**(2026-09-11 현장 확인). 4대는 "구해지면" 보조 |
| **인쇄 한 장 실제 소요시간** | ⏳ **외부 확인 대기 — 2026-09-11 장학사께 요청됨.** 🔴 이 값 하나가 §1의 유일한 위험(3분이면 60장 부족)을 확정하거나 없앤다 |
| **인화지 팩 규격·필요 팩 수** | ⏳ **외부 확인 대기 — 2026-09-11 장학사께 요청됨**(권장 400장 기준) |
| 연속 출력 시 몇 장째부터 느려지는가 | ⏳ 스펙은 "연속 시 1~2분"으로만 적혀 있다. §2의 과열 완충재와 함께 봐야 한다 |

**이 세션은 대기 항목을 다시 여쭙지 않는다** — 답이 오면 전달받아 표의 줄을 고르면 된다.
