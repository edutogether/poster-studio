- **주소는 두 개이고 둘 다 살아 있다**(2026-09-10 대표 지시로 정식 주소가 붙었다).
  - **`https://poster.edutogether.kr` — 정식 주소.** 사람에게 주는 주소, 안내문·QR을 **새로 만들 때**
    쓰는 주소는 전부 이것이다. `http`로 들어와도 301로 `https`로 넘어간다(실측).
  - **`https://poster-studio.web.app` — 없애지 않는다.** 이미 나간 QR·링크가 죽으면 안 된다.
    두 주소는 같은 것을 서빙한다(번들 해시까지 같은 것을 확인).
  - 🟢 **인쇄물·QR은 이 저장소 밖에서 제작되며, 주소 정리의 제약이 아니다**(2026-09-10 Bumm님 확인:
    "QR 안내물은 신경 쓰지 말고 하면 된다"). 새로 만드는 것은 정식 주소를 쓴다. 이미 제작된 것이
    옛 주소를 담고 있어도 문제가 없는데, **옛 주소가 계속 통하는 것을 CI가 매 배포마다 확인**하기
    때문이다(홈 200 · 나가면 안 되는 경로 404 · CORS 오리진 반사, 하나라도 실패하면 배포 실패).
  - 🟠 **그렇다고 옛 주소를 없애도 된다는 뜻이 아니다.** 옛 주소를 지키는 이유는 인쇄물이 아니라
    **이미 나간 링크가 죽지 않게** 하는 것이다(포털 카드, 공유된 주소 등). 인쇄물 제약이 없다는
    말을 "이제 옛 주소를 정리해도 된다"로 읽지 않는다.
    ⚠ **"옛 주소가 살아 있다"는 이 저장소에서 가정이 아니라 검사로 고정된 사실이다.**
    2026-09-10 실측으로는 OPTIONS뿐 아니라 **옛 오리진으로 보낸 실제 `/generate` 요청도 400**
    (사진 없는 요청의 정상 응답)이었다.
    이 줄을 굳이 적는 이유: **같은 날 AI Ways에서 옛 주소가 실제로는 죽어 있는 것이
    나왔다**(`ALLOWED_ORIGINS`에서 빠져 `403 invalid_origin`). org 전체가 "옛 주소는
    살아 있다"를 근거 없이 물려받고 있었다. **근거 없이 물려받은 전제가 가장 위험하다** —
    그래서 여기서는 그 전제가 무엇으로 보장되는지까지 적어 둔다.
  - ⚠ **`deploy.yml`·`firebase.json`·`.firebaserc`의 `poster-studio`는 주소가 아니라 배포 대상
    식별자다.** 주소를 바꿨다고 여기를 따라 고치면 배포가 깨진다.
  - ⚠ `functions/index.js`의 `ALLOWED_ORIGINS`에는 **두 주소가 다 들어 있어야 한다**(한쪽만 두면
    다른 쪽에서 CORS로 막힌다). 목록의 앵커 규칙은 아래 "절대 하면 안 되는 것" 참고.
  - 🟠 **`functions/test/index.test.js`의 "옛 주소를 허용한다" 테스트를 지우지 않는다.**
    정식 주소가 생겼으니 옛 주소 테스트는 낡아 보이지만, **그게 옛 주소를 지키는 유일한 장치다** —
    지우면 나중에 누가 `ALLOWED_ORIGINS`에서 옛 주소를 빼도 아무도 못 잡고, 이미 인쇄된 QR로
    들어온 사람이 CORS에 막힌다. 테스트를 지우기 전에 **그 테스트가 무엇을 지키고 있는지**를 먼저 읽는다.
  - 🟢 CI가 배포 직후 **두 주소를 다 확인한다**(홈 200 · 나가면 안 되는 경로 404 · CORS 오리진 반사).
    **하나라도 실패하면 배포가 실패**한다 — 하나만 살아도 통과시키면 다른 하나가 죽은 걸 못 잡는다.

## 카카오톡·SNS 공유 카드 (2026-09-10 대표 지시)
- `index.html`의 og 태그가 카카오톡에 뜨는 카드다. 값은 **포털(`apps.ts`)이 확정한 6개 앱
  공통 규칙**이고 `og:title`은 **`{앱 이름} | {hook}`** 형식이다 — 임의로 바꾸지 않는다.
- 🟡 **그림은 이 도메인에서 직접 배포한다**(`public/og.jpg` → `dist/og.jpg` → `/og.jpg`).
  포털 주소를 그대로 가리키면 **다른 저장소의 배포가 막힐 때 여섯 앱의 공유 카드가 같이
  멈춘다** — 2026-09-10에 포털 CI가 40분 넘게 막힌 일이 실제로 있었다.
- 🟡 **이 방식의 유일한 약점: 포털이 카드 그림을 바꾸면 여기도 같이 바꿔야 한다.**
  원본은 `https://edutogether.kr/assets/og/poster.jpg`(1200×630)다. 포털 쪽이 바뀌었다는
  말을 들으면 그 파일을 다시 받아 `public/og.jpg`를 교체하고 배포한다.
- 🟡 **카카오톡은 한 번 잡은 카드를 오래 캐시한다.** 그래서 **한 번에 맞는 값으로 나가야 하고**,
  확인은 이미 공유해 본 주소가 아니라 **새 링크**로 해야 한다(쿼리스트링을 붙이는 식).
  값을 틀린 채로 한 번 공유하면 고쳐도 한동안 옛 카드가 뜬다.
- 확인은 문자열이 아니라 결과로 한다 — 배포 후 `curl`로 (1) 라이브 `index.html`에 태그가
  실제로 나가는지, (2) **`og:image` 주소를 직접 받아 200 · `image/jpeg`인지**.
  주소만 바꾸고 파일이 없으면 카드에 그림이 안 뜬다.
- 🟢 이 앱에는 서비스워커가 없으므로 `og.jpg`가 프리캐시에 끼어들 여지가 없다(2026-09-10 확인).
- ⚠ **og 문구를 바꾸면 폰트 서브셋도 다시 만들어야 한다.** `charset.mjs`가 `content=` 속성까지
  훑기 때문이다. 실제로 og를 넣자 `딱뚝특` 3자가 없어 CI가 막았다(2026-09-10).
  **화면에 안 나오는 문구인데도 서브셋에 넣는 쪽을 택했다** — 빼려면 추출기에서 `content`를
  제외해야 하는데, 그건 **덜 모으는 방향**이라 언젠가 진짜 화면 문구를 놓친다. 글자 몇 개
  더 담는 비용(408자, 195.7KB)이 두부(□)가 나갈 위험보다 훨씬 싸다.
  절차: `npm run fonts:charset` → `python scripts/fonts/subset.py` → `npm run fonts:check`.
  🟠 서브셋을 다시 만들면 `fonts:check`가 **주소의 판(`?v=`)이 낡았다고 실패**한다 — 알려 주는 판으로 주소 전부를
  바꾼다(2026-10-09). 서브셋은 이름이 고정이고 30일 캐시라, 판을 안 바꾸면 이미 받은 브라우저가 옛 파일을 30일 쓴다.

## «움직임 줄이기» 신호를 읽지 않는다 (2026-11-11 Bumm님 «가. 늘 돌게 하기» → 같은 날 «여덟 앱 모두 같은 규칙: 움직임 줄이기 신호로 멈추는 것은 하나도 남기지 않는다», 팀장 전달)
- 🔴 **스플래시 막대 · 로고, 촬영 예시 영상(개인 · 단체 — 재생과 1단계 미리 받기), 로딩 화면(대기 영상 · 장면 넘김 · 점)은 «움직임 줄이기»(`prefers-reduced-motion: reduce`) 신호로 멈추지 않는다.**
  예시 영상은 장식이 아니라 «이렇게 서세요» 안내이고, 행사 노트북에도 모르게 이 신호가 켜져 있을 수 있다. Bumm님이 원격으로 이 PC의 크롬을 열자 Windows 애니메이션이 켜져 있는데도(콘솔 세션 SPI 1)
  크로미움이 reduce로 보고해 세 화면이 멈춰 있었다. 자동 재생 거부 · 오류 · 4초 정체 때 정지 그림으로 가는 처리는 그대로다.
- 🔴 **장식도 그 신호로 끄지 않는다 — 화면 코드(`src` 전체 · `public` · 진입 HTML) 어디서도 `prefers-reduced-motion`을 읽지 않는다**(CSS `@media` · JS `matchMedia` 모두).
  처음(«가»)에는 바뀜(transition) · 부드러운 스크롤 · 첫 화면 «아래로» 화살표 · 촬영 중 빨간 점 깜빡임 · 휴대폰 3단계 넘김 안내 · 장르 카드 · 단추 올림 효과를 남겼는데,
  여덟 앱을 같은 규칙으로 맞추며 모두 지웠다(`19299f6`). 다시 넣지 않는다 — `test/reduced-motion.test.ts`가 주석을 뺀 코드에서 그 신호 이름이 한 번이라도 나오면 걸린다.
- 🟠 **확인 도구는 «줄이지 않음»을 흉내 내 재지 않는다 — reduce와 no-preference 두 조건으로 잰다.** 11/10에 `camera-example-probe.mjs`가 원격 크롬의 reduce 때문에 «재생되지 않았다»로 걸리자
  «줄이지 않음» 흉내만 넣어 통과시켰고(8d52896), 실제 사용자 화면이 멈춘 것을 놓쳤다 — **흉내로 PC 설정을 지우고 재면 실제 사용자 화면을 놓친다.**
  `reduced-motion-probe.mjs <주소> <폴더> --playwright <playwright-core 부모 폴더>`(스플래시 · 개인 · 단체 · 로딩 · 단추 바뀜, 휴대폰은 «아래로» 화살표 · 3단계 넘김 안내까지, 기본 두 조건 ·
  `--force`는 크롬을 `--force-prefers-reduced-motion`으로 띄워 브라우저 설정 자체가 reduce인 상태), `camera-example-probe.mjs` · `waiting-videos-live.mjs` · `splash.mjs`도 두 조건이다.
  CI에서는 `test/reduced-motion.test.ts`가 소스를 본다(일부러 옛 코드로 되돌려 걸리는 것 확인 — 11/11 판 7개 파일이 걸렸다).

- 로컬 실행: `npm run dev`(Vite). 라이브와 같은 형태로 보려면 `npm run build` 후 `dist/`를
  정적 서버로 연다(포트 5500 또는 8080 — `ALLOWED_ORIGINS`에 이미 허용돼 있음).

  3단계가 곧장 열린다(2026-10-14 Bumm님). `import.meta.env.DEV` 갈래라 **운영 빌드에서는 코드가 통째로 빠진다**(dist 번들에 `"posters"` 0건,
  dist 서버에 같은 주소를 주면 1단계 그대로 — 확인함). 서버·카메라·AI 요청 0건.
  AI 생성은 로컬에서도 라이브 Functions를 호출하므로 **실비용이 나간다**.
- 에뮬레이터: 사용하지 않는다. 헤더(CSP 등) 확인이 필요하면 `firebase emulators:start --only hosting`.
- 배포: `master`에 push → CI가 test → functions → hosting 순으로 자동 배포. 수동 배포는 하지 않는다
  (예외: `keepWarm` 스케줄 변경 배포, GitHub 정지 중 로컬 배포 — `_docs/ops/runbook.md` §9와 아래 절 참고).

- 🟡 **검사는 "무엇이면 통과인가"를 명시하고 그 외 전부를 실패로 둔다**(허용 목록, 금지 목록 아님).

  **내 커밋의 실행이 아니다.** 푸시 직후에는 아직 실행이 안 잡혀서 **직전 성공을 보고 "성공"이라고

  좁히는 건 덜 모으는 방향이고, 그러면 언젠가 진짜 화면 문구를 놓쳐 두부(□)가 나간다.
