# Intent 워크플로

이 문서는 `_docs/intents/`를 쓰는 모든 저장소가 공유하는 규칙 원본이다. 원본은
`D:\Projects\_shared\intent-kit\intent-workflow.md` 하나뿐이고, 각 저장소는
`.claude/rules/intent-workflow.md`에 이 파일의 사본을 둔다(그래야 git에 들어가고,
그 저장소만 따로 클론해도 규칙이 같이 딸려온다). 사본을 고칠 일이 생기면 원본을
먼저 고치고 다시 복사한다 — 사본에서 직접 고치지 않는다.

## 이게 왜 있는가

CLAUDE.md는 "이 저장소는 항상 이렇게 동작한다"는 **상시 규칙**을 담는다. intent
문서는 그것과 다르다 — **지금 하려는 이 작업 하나**가 왜 필요하고, 뭘 원하고,
어떤 제약 안에서 해야 하는지를 코드를 건드리기 전에 짧게 적어두는 것이다. 계획을
세우기 전에 "내가 지금 뭘 풀려는 건지"를 스스로 명확히 하는 게 목적이고, 나중에
그 결정을 다시 찾아볼 수 있는 기록이 되는 게 부수 효과다.

## 등급 — 모든 작업에 다 필요한 건 아니다

| 등급 | 해당하는 것 | 해야 할 것 |
|---|---|---|
| **0** | 오탈자, 명백한 버그 수정, 이미 확정된 결정의 재확인·재적용 | intent 문서 없이 바로 진행 |
| **1** | 여러 파일/화면에 걸치거나, 되돌리기가 약간 번거롭거나, 방향은 명확하지만 구현 선택지가 여럿인 작업 | 간단한 intent.md(문제/원하는 결과/제약만) 작성 후 진행 |
| **2** | 사용자 데이터, 과금/요금제, 보안·권한, 배포 파이프라인, 실사용자 경험에 영향을 주거나, 되돌리기 어려운 작업 | 전체 필드를 다 채운 intent.md 작성. 미결 질문이 있으면 반드시 멈추고 사용자에게 확인 |

애매하면 한 등급 위로 잡는다 — intent 문서 하나 더 쓰는 비용이, 잘못된 가정으로
되돌리기 어려운 걸 만드는 비용보다 항상 싸다.

## 절대 규칙

1. **제약은 협상 대상이 아니다.** intent.md의 "제약" 항목에 적힌 걸 지키면서
   구현할 수 없다는 걸 발견하면, 알아서 완화하지 말고 **멈추고 사용자에게 묻는다.**
2. **추측한 값을 사실처럼 적지 않는다.** 확인 못 한 건 "[확인]" 표시를 남기거나
   "미결 질문"에 올린다. 나중에 "그때 이렇게 가정했다"보다 "그때 이걸 몰랐다"가
   훨씬 낫다.
3. **선택지가 갈리면 하나로 좁혀서 제시하지 않는다.** 장단점을 나란히 보여주고
   사용자가 고르게 한다 — 이게 세션이 대신 정할 일인지 아닌지 애매하면 항상
   "사용자가 고를 일"쪽으로 판단한다.
4. **intent.md는 작업 시작 전에 쓴다.** 코드를 먼저 짜고 나중에 끼워맞춰 쓰지
   않는다 — 그러면 "왜 이렇게 했는지"가 아니라 "이미 한 걸 정당화하는 글"이 되어
   버려서 원래 목적을 잃는다.

## 폴더 구조

```
_docs/intents/
  README.md              (등급표 + 인덱스 표 — README-template.md에서 복사)
  TEMPLATE.md             (TEMPLATE.md에서 복사, 새 intent 쓸 때 이걸 복사해서 시작)
  00-charter.md            (선택 — 초기 개발 단계에서 건별 intent 대신 쓰는 전체 헌장)
  YYYY-MM-DD-슬러그/
    intent.md
```

## 상태

intent.md의 frontmatter `status`에 상태를 적는다(폴더 이동으로 표시하지 않는다):

`draft`(작성 중) → `accepted`(이 방향으로 하기로 승인됨) → `in-progress`(작업 중)
→ `done`(반영 완료) | `dropped`(안 하기로 함, 이유를 한 줄 남김)

**상태를 바꾸는 것은 Bumm님이다.** 세션이 임의로 `draft`를 `accepted`로 올리지 않는다 —
승인을 기록하는 자리이기 때문이다. 상태가 바뀔 때마다 별도 커밋으로 남긴다
(예: `docs: intent(슬러그) accepted (승인 Bumm 9/6)`).

`done`이 됐다고 폴더를 지우지 않는다 — 나중에 "왜 그때 이렇게 안 했지"를 다시
물었을 때 답할 수 있는 기록이 그 자체로 가치가 있다.
