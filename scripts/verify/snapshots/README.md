# 포스터 픽셀 지문 — "1픽셀도 안 바뀌었다"의 증거

2026-09-09 폰트 서브셋 작업 때 대표님이 건 절대 조건은 **"아이가 인쇄해 가는 포스터가
1픽셀도 달라지면 안 된다"**였다. 그걸 눈으로 확인할 방법이 없어서
[`../poster-pixels.js`](../poster-pixels.js)를 만들어 **입력 5종 × 템플릿 4종 = 20장**의
SHA-256 지문을 떴다. 여기 있는 네 파일이 그때 실제로 뜬 값이다.

| 파일 | 언제 |
|---|---|
| `poster-pixels-BEFORE.json` | 서브셋 적용 **전** |
| `poster-pixels-BEFORE2.json` | 같은 코드로 **한 번 더** (도구가 결정적인지 확인용) |
| `poster-pixels-AFTER.json` | 서브셋 적용 **후**, 굵기 600을 넣기 **전** |
| `poster-pixels-AFTER2.json` | 굵기 600을 넣은 **뒤** = 최종 |

## 무엇이 나왔나

```
BEFORE vs BEFORE2   불일치 0/20   <- 도구가 결정적이다(이게 먼저 성립해야 나머지가 의미를 가진다)
BEFORE vs AFTER     불일치 1/20   <- 단체·출연진·미스터리 / 클래식
BEFORE vs AFTER2    불일치 0/20   <- 최종. 조건 충족
```

## 그 1건이 중요한 이유 — 서브셋이 만든 결함이 아니다

클래식 판은 **출연진 줄을 굵기 600으로** 그리는데 `ensureGlyphs()`의 굵기 목록에 600이
빠져 있었다. 서브셋 전에는 화면 UI가 이미 Pretendard 600을 받아둔 상태라 캔버스가
그 덕을 봐서 **누락이 가려져 있었다.** UI 폰트를 서브셋으로 갈라내자 그 우연이
사라지면서 드러났다 — **원래 있던 누락**이고, 안 잡았으면 **단체 포스터의 출연진 줄만
다른 글꼴로 인쇄되어 나갔을 것**이다.

## 다시 뜨는 법

`grain()`이 `Math.random()`을 쓰므로 그냥 두 번 만들면 매번 다르다(실측 0.03~1.2% 차이).
`poster-pixels.js`가 난수를 씨앗 있는 생성기로 갈아끼워 결정적으로 만든다. **페이지를
새로 로드한 상태에서** 돌려야 한다(grain 타일이 모듈에 캐시된다).

```js
await fetch('http://localhost:5501/scripts/verify/poster-pixels.js')
  .then(r => r.text()).then(t => (0, eval)(t));
await window.__posterPixels();
```
