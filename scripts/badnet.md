# 나쁜 네트워크 수동 테스트 체크리스트

크롬 DevTools의 커스텀 네트워크 스로틀로 행사장에서 있을 수 있는 열악한 와이파이 상황을 흉내내 직접 확인한다. 자동화된 스크립트가 아니라 사람이 직접 눈으로 확인하는 절차다.

## 준비

1. `https://poster.edutogether.kr` 접속.
2. 크롬 개발자도구(F12) → **Network** 탭 → 상단 "No throttling" 드롭다운 → **Add custom profile...**
3. 아래 값으로 커스텀 프로필 생성:
   - **Download**: 5 Mbps (5,000 Kbps)
   - **Upload**: 2 Mbps (2,000 Kbps)
   - **Latency**: 300 ms
4. 만든 프로필을 선택해 적용한 상태로 아래 체크리스트를 진행한다.

## 체크리스트

### 1. 150초 타임아웃 시 실제로 뜨는 UI 확인
- [ ] 카메라로 촬영 → 정보 입력 → "AI 포스터 만들기" 클릭.
- [ ] 클릭 직후부터 실제로 응답이 오거나 실패 처리될 때까지 화면을 지켜본다(스로틀 때문에 정상보다 오래 걸릴 수 있음 — 필요하면 Network 탭에서 "Offline"으로 잠깐 전환해 150초 타임아웃 자체를 강제로 유발해도 됨, `public/api.js`의 `AbortController` + `150_000`ms 타임아웃 참고).
- [ ] 타임아웃이 실제로 발생했을 때 화면에 뜨는 문구/버튼이 무엇인지 기록한다.
- [ ] 그 문구가 사용자(부스 진행자·학생)가 이해하기에 충분히 명확한지 판단한다.

### 2. 재시도 진행 중임을 알리는 표시가 있는지
- [ ] 생성 요청이 오래 걸리는 동안(스피너가 도는 동안) 화면에 "진행 중"과 "재시도 중"을 구분할 수 있는 표시가 있는지 확인한다.
- [ ] 현재 `public/api.js`의 스피너 문구(`AI가 그리는 중… N초`)가 경과 시간만 보여주는지, 재시도 여부까지 보여주는지 확인하고 기록한다.

### 3. 실패 시 "AI 없이 계속하기" 버튼이 실제로 동작하는지
- [ ] 생성이 실패하도록 유도한다(Offline 토글로 요청 자체를 끊거나, 응답을 기다리다 실패 문구가 뜨는 것을 확인).
- [ ] "🎨 AI 없이 기본 버전으로 계속하기" 버튼이 화면에 나타나는지 확인한다.
- [ ] 버튼을 눌렀을 때 실제로 단색/그라디언트 배경의 대체 포스터가 만들어지고, 인쇄 화면까지 정상적으로 이어지는지 확인한다.

### 4. 네트워크 복구 후 재생성이 정상 동작하는지
- [ ] 스로틀/오프라인 상태를 원래대로("No throttling") 되돌린다.
- [ ] 실패했던 화면에서 다시 "AI 포스터 만들기" 또는 "🔄 다른 그림으로"를 눌러 정상적으로 재생성이 되는지 확인한다.
- [ ] 재생성 한도(사진 1장당 최초 1회+재생성 1회, 총 2회)가 실패한 시도까지 소모했는지, 아니면 실패한 시도는 한도에서 빠지는지 확인해 기록한다(현재 서버 로직상 실패한 요청도 `checkPhotoGenerationLimit` 카운트를 소모하는지 `functions/index.js` 확인 필요 — 이 문서는 UI 동작 확인용이고, 카운트 소모 여부는 코드로 별도 확인할 것).

## 기록 방법

각 항목을 체크하면서 스크린샷 또는 짧은 메모를 남긴다. 이 문서 자체를 자동으로 채우는 스크립트는 없다 — 사람이 직접 진행하고 결과를 아래처럼 채워 넣는다.

```

2. 재시도 표시: (있음/없음) — 메모:
3. AI 없이 계속하기 버튼: (정상 동작/문제 있음) — 메모:
4. 네트워크 복구 후 재생성: (정상 동작/문제 있음) — 메모:
```
